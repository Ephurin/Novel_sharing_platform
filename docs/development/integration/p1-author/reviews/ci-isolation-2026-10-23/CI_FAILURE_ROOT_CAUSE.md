## 1. Executive Summary

In GitHub Actions workflow run `39902374069`, the job `frontend-api-cutover` failed during the step `Backend typecheck and deterministic tests` with exit code 1.

The failure was not caused by a regression or logical defect in the production `acceptDraft` endpoint or backend Core code. Instead, it was an orchestration and test isolation mismatch:

1. **Test Discovery Mismatch:** The step executed `find src -name '*.test.ts' ! -name '*.live.test.ts' ! -name '*.postgres.test.ts'`. Because `backend/src/modules/novels/accept-draft-contract.test.ts` was named without `.postgres.` or `.live.`, it was categorized as a pure deterministic unit test.
2. **Environment Isolation Deficit:** The job `frontend-api-cutover` does not provision a live PostgreSQL container (running `DATABASE_URL: postgresql://postgres:postgres@localhost:5432/ephurin_ci_placeholder`).
3. **Connection Refusal:** `accept-draft-contract.test.ts` opened a PostgreSQL connection in its `before()` hook (`getPostgresPool().query(...)`). Attempting to connect to `127.0.0.1:5432` threw `connect ECONNREFUSED 127.0.0.1:5432`.
4. **Cascading Cancellation:** The Node test runner aborted the test suite hook, cancelling all 14 child tests and exiting with code 1.

### 2.2 Schema Dependency Finding

Further analysis of `accept-draft-contract.test.ts` revealed a secondary fixture isolation risk:
In Test 11 (`rejects with 409 OBJECTIVE_INTENT_SUPERSEDED if P3 controller intent changed or plan missing`), `acceptDraft` invokes `assertControllerIntent()`, which executes:
```sql
SELECT * FROM narrative.autonomous_runs WHERE id=$1 AND novel_id=$2 AND created_by=$3 FOR UPDATE
```
In a fresh PostgreSQL database that has only undergone backend migrations (`migrate.ts`, migrations 001–017), the schema `narrative` and table `narrative.autonomous_runs` (normally generated by Python Alembic migrations in `ai-service`) do not exist. When run against a fresh backend-only database, this threw:
```text
error: relation "narrative.autonomous_runs" does not exist
```
This was a secondary prerequisite failure for isolated integration environments.

## 3. Remediation Strategy

To preserve all 14 trust-contract tests without weakening any assertions:

1. **Deterministic Test Discovery Isolation:**
   In `.github/workflows/p8-cutover.yml`, exclude `accept-draft-contract.test.ts` from `frontend-api-cutover`'s deterministic test discovery:
   `find src -name '*.test.ts' ! -name '*.live.test.ts' ! -name '*.postgres.test.ts' ! -name 'accept-draft-contract.test.ts'`
   This guarantees pure unit tests (91 tests across 18 files) run deterministically in sub-second time without any database dependency.

2. **Dedicated Database Integration CI Job (`backend-integration`):**
   Add a dedicated job in `.github/workflows/p8-cutover.yml` provisioning:
   - `services: postgres` (`pgvector/pgvector:pg16`)
   - `services: mongodb` (`mongo:7`)
   - Healthcheck & socket readiness verification
   - Automatic execution of backend schema migrations (`npx tsx src/core/database/migrate.ts`)
   - Complete execution of `accept-draft-contract.test.ts` (14/14 tests)
   - Complete execution of `p1-production-persistence.postgres.test.ts` (5/5 tests)

3. **End-to-End Compose Integration Gate:**
   In `root-compose-cutover-smoke`, execute `accept-draft-contract.test.ts` inside the running backend container against the live Compose PostgreSQL stack:
   `docker compose exec -T backend npx tsx --test --test-force-exit src/modules/novels/accept-draft-contract.test.ts`

4. **Self-Sufficient Fixture Lifecycle:**
   In `backend/src/modules/novels/accept-draft-contract.test.ts`:
   - In `before()`: Execute idempotent `CREATE SCHEMA IF NOT EXISTS narrative` and define minimal `narrative.autonomous_runs`, `narrative.story_plans`, and `narrative.story_plan_objectives` tables so controller intent validation operates cleanly in standalone backend integration environments.
   - In `after()`: Add explicit fixture teardown deleting inserted `chapter_revisions`, `chapters`, `novels`, and `users` rows.
