## 2. Technical Findings & Root-Cause Resolutions

### Finding 1: PostgreSQL `RevisionProvenanceRecord` Broken at ORM/Schema Level
- **Root Cause**: `RevisionProvenanceRecord` in `ai-service/infrastructure/orm_models.py` omitted the `revision_id` column and unique constraint `(tenant_id, novel_id, revision_id)`. Inserts in repository also omitted `story_brain_id`, violating a `nullable=False` foreign key.
- **Code & Migration Changes**:
  - `ai-service/infrastructure/orm_models.py`:
    ```python
    class RevisionProvenanceRecord(Base):
        __tablename__ = "revision_provenances"
        __table_args__ = (
            UniqueConstraint("tenant_id", "novel_id", "revision_id", name="uq_rev_provenance_revision"),
            {"schema": SCHEMA},
        )
        id: Mapped[uuid.UUID] = mapped_column(Uuid, primary_key=True)
        story_brain_id: Mapped[uuid.UUID] = mapped_column(
            Uuid, ForeignKey(f"{SCHEMA}.story_brains.id", ondelete="CASCADE"), nullable=False
        )
        tenant_id: Mapped[uuid.UUID] = mapped_column(Uuid, nullable=False, index=True)
        novel_id: Mapped[uuid.UUID] = mapped_column(Uuid, nullable=False, index=True)
        chapter_id: Mapped[uuid.UUID] = mapped_column(Uuid, nullable=False)
        revision_id: Mapped[uuid.UUID] = mapped_column(Uuid, nullable=False, index=True)
        chapter_number: Mapped[int] = mapped_column(Integer, nullable=False)
        created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())
    ```
  - `ai-service/migrations/versions/0006_fix_revision_provenance.py`: Added migration ensuring `revision_id`, `uq_rev_provenance_revision`, and index exist on existing and clean databases.
  - `ai-service/infrastructure/postgres_narrative_repository.py`: In `create_bootstrap_job` and `record_revision_provenance`, ensured `brain = self._get_or_create_brain(session, novel_id)` is fetched and `story_brain_id=brain.id` is explicitly passed.
  - Added repository query method `get_revision_provenance(story_id, revision_id)`.
- **Test Evidence**: `docs/development/P6.5-R3-PRODUCTION-PATH-CLOSURE-01/postgres-integration.log` (`test_alembic_migrations_lifecycle`, `test_revision_provenance_lifecycle`).

### Finding 2: Canonical Event Chapter Provenance & Temporal Isolation
- **Root Cause**: `extract_narrative_events` defaulted to `chapter_num = 1`, and `RevisionAnalysisService` did not pass canonical `revision.chapter_number`. When materializing events, `accept_proposal_group` defaulted to `int(payload.get("chapter", 1))` without consulting trusted revision provenance records.
- **Code Changes**:
  - `ai-service/application/revision_analysis_service.py`:
    - Passed `chapter_num=chapter_number if chapter_number is not None else 1` to `extract_narrative_events`.
    - Populated canonical `chapter_number` and `chapter_id` in proposal payload and evidence.
  - `ai-service/infrastructure/postgres_narrative_repository.py` and `in_memory_narrative_repository.py`:
    - In `accept_proposal_group` for `proposal_type == "event"`, resolved `chapter_number` from `RevisionProvenanceRecord` matching `evidence["revision_id"]`, falling back to `evidence["chapter_number"]`, payload, or 1.
    - Stored canonical chapter in `EventRecord.chapter_number`.
    - Temporal context projection (`get_structured_context`) selects events where `EventRecord.chapter_number <= chapter_number` and filters transitions by `event_id.in_(active_event_uuids)`.
- **Test Evidence**: `docs/development/P6.5-R3-PRODUCTION-PATH-CLOSURE-01/postgres-integration.log` (`test_chapter_25_event_and_state_isolation_from_chapter_5`).

### Finding 3: Service-Auth Boundary Coverage on `/v1/enhanced`
- **Root Cause**: `api/interactions.py` router `APIRouter(prefix="/v1/enhanced")` was mounted without `dependencies=[Depends(require_service_token)]`, allowing direct unauthenticated bypass to `/v1/enhanced/kb/{story_id}` and `/v1/enhanced/relation/override`.
- **Code Changes**:
  - `ai-service/api/interactions.py`:
    ```python
    router = APIRouter(
        prefix="/v1/enhanced",
        tags=["interactions"],
        dependencies=[Depends(require_service_token)],
    )
    ```
  - Unauthenticated requests to any endpoint under `/v1/enhanced/*` receive HTTP 401 `SERVICE_AUTH_REQUIRED`. Requests with invalid token receive HTTP 403 `SERVICE_AUTH_INVALID`. Requests with valid service token pass. Public `/health` endpoint remains accessible.
- **Test Evidence**: `docs/development/P6.5-R3-PRODUCTION-PATH-CLOSURE-01/service-auth.log`.

### Finding 4: Outbox Claim Concurrency & Lease Semantics
- **Root Cause**: `claimPendingOutboxEvents` selected `status in ('PENDING', 'PROCESSING') FOR UPDATE SKIP LOCKED` and immediately committed the transaction. Once committed, locks were released, allowing a concurrent worker to claim the active `PROCESSING` event.
- **Code Changes**:
  - `backend/src/modules/novels/outbox.repository.ts`:
    - Updated `claimPendingOutboxEvents` and `fetchPendingOutboxEvents` with true lease semantics:
      ```sql
      SELECT *
      FROM revision_outbox_events
      WHERE (
        (status = 'PENDING' AND next_retry_at <= now())
        OR
        (status = 'PROCESSING' AND updated_at <= now() - ($2 || ' seconds')::interval)
      )
      ORDER BY created_at ASC
      LIMIT $1
      FOR UPDATE SKIP LOCKED;
      ```
    - Claimed rows are atomically updated: `SET status = 'PROCESSING', updated_at = now()`.
    - Invariant maintained: Only one active worker can process an event. Stale processing events (>300s timeout) are recovered if a worker crashes.
- **Test Evidence**: `docs/development/P6.5-R3-PRODUCTION-PATH-CLOSURE-01/backend-integration.log` (multi-worker concurrency & expired lease recovery tests).

### Finding 5: Consistency Semantics Guarantee Declaration
- **Semantics Declaration**:
  - `fail-closed availability + best-effort freshness`.
  - Accept-time verification queries AI Story Brain freshness with service token authentication.
  - If AI service is unreachable or returns non-200, accept fails closed with HTTP 503 (`AI_SERVICE_UNAVAILABLE`).
  - If current brain version > generation `brain_version_used`, accept fails closed with HTTP 409 (`BRAIN_VERSION_CONFLICT`).
  - Cross-service atomic distributed transactions (e.g. 2PC across PostgreSQL and AI service storage) are acknowledged as out of scope for Phase 6.5 MVP.
