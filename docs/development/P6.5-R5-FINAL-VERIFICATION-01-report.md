## 1. Chi Tiết Khắc Phục Các Điểm Chặn Kỹ Thuật

### 1.1. Di Trú Xuất Xứ Ngữ Nghĩa (Semantic Legacy Provenance Migration - P1)
- **Vấn đề**: `0006_fix_revision_provenance.py` ở đợt R4 thực hiện `SET revision_id = gen_random_uuid()` trên các hàng 0005 cũ. Điều này bảo toàn schema nhưng phá vỡ ngữ nghĩa truy vấn (`_stable_uuid("revision", external_rev_id)` không bao giờ khớp UUID ngẫu nhiên).
- **Giải pháp**:
  1. Loại bỏ triệt để lệnh `gen_random_uuid()` trong `0006_fix_revision_provenance.py`.
  2. Triển khai cơ chế kiểm tra fail-closed có hướng dẫn xử lý cụ thể (`actionable error`):
     - Khi phát hiện các hàng cũ có `revision_id IS NULL`, migration kiểm tra biến môi trường `MIGRATION_CLEAR_UNMAPPED_PROVENANCE`.
     - Nếu chưa được bật, migration chủ động ném `RuntimeError` chi tiết, từ chối việc tự động gán ID giả mạo.
     - Nếu cờ `MIGRATION_CLEAR_UNMAPPED_PROVENANCE=true` được bật (hoặc sau khi làm sạch thủ công), migration xóa các hàng cache không thể phục hồi và hoàn tất nâng cấp schema (`NOT NULL`, constraint `uq_rev_provenance_revision`, index).
  3. Cung cấp quy trình tái tạo xuất xứ chính thức thông qua `repo.record_revision_provenance`.
  4. Cập nhật bài kiểm thử `test_migration_upgrade_from_legacy_0005_schema` trong `tests/test_postgres_integration.py`:
     - Kiểm chứng migration ném lỗi từ chối khi không có cờ (không bịa UUID).
     - Kiểm chứng với cờ controlled rebuild, migration thành công và `get_revision_provenance(novel_id, original_revision_id)` phục hồi chính xác `chapter_number` ban đầu.
- **Bằng chứng**: `docs/development/P6.5-R5-FINAL-VERIFICATION-01/migration-semantic.txt`.

### 1.2. Thắt Chặt API Fencing Của Outbox (P2)
- **Vấn đề**: `markOutboxEventCompleted` và `markOutboxEventFailed` vẫn cho phép `claimToken` là tùy chọn, tạo nguy cơ vô tình gọi unfenced finalize trong production.
- **Giải pháp**:
  1. Trong `backend/src/modules/novels/outbox.repository.ts`, đặt tham số `claimToken: string` là **bắt buộc** cho cả `markOutboxEventCompleted` và `markOutboxEventFailed`. Ném ngoại lệ ngay lập tức nếu thiếu token.
  2. Tách riêng các hàm phụ trợ quản trị rõ ràng: `markOutboxEventCompletedUnfenced` và `markOutboxEventFailedUnfenced`.
  3. Cập nhật `backend/src/jobs/outbox-processor.ts` kiểm tra nghiêm ngặt `event.claimToken` trước khi kết thúc sự kiện.
  4. Cập nhật bài kiểm thử cạnh tranh `outbox.postgres.test.ts` lọc theo đúng `event.eventId`, bảo đảm tính tất định 100%.
- **Kết quả**: 25/25 bài kiểm thử backend đạt `PASS` (`npm test`), `npm run typecheck` đạt 0 lỗi.

### 1.3. Live System Smoke & Gateway Auth Probes (P1)
- **Bối cảnh môi trường**: Dịch vụ `com.docker.service` (Docker Desktop) trên máy trạm Windows yêu cầu quyền Administrator để khởi động Windows service. Cơ sở dữ liệu PostgreSQL 18 (port 5432) và MongoDB 7 (port 27017) đang chạy native trực tiếp trên host. Toàn bộ kiểm thử live smoke được thực hiện trực tiếp trên các tiến trình live process (`ai-service` port 8000 và `backend` port 4000) kết nối vào cơ sở dữ liệu thật.
- **Kết quả kiểm thử live**:
  1. **Direct AI `/health`**: Trả về HTTP 200 `{"status": "ok"}`.
  2. **Direct AI Missing Token**: Request tới route được bảo vệ không kèm token trả về HTTP 401 `SERVICE_AUTH_REQUIRED`.
  3. **Direct AI Invalid Token**: Request kèm `Bearer bad-token` trả về HTTP 403 `SERVICE_AUTH_INVALID`.
  4. **Direct AI Valid Token**: Request kèm `Bearer <PLATFORM_SERVICE_TOKEN>` trả về HTTP 200 với dữ liệu Story Brain từ PostgreSQL.
  5. **PostgreSQL Narrative Repository**: Đã áp dụng toàn bộ Alembic migration (0001 -> 0006) lên database `ephurin` và xác nhận repository sử dụng `PostgresNarrativeRepository`.
  6. **Node Gateway Forwarding & Context Preview**:
     - Đăng ký và cấp quyền author trên Backend.
     - Tạo novel và chapter mới.
     - Gọi `GET /api/v1/ai/story-brains/by-novel/:novelId` qua Node Gateway -> Node Gateway xác thực tác giả, tự động inject service token, AI Service phản hồi thành công (HTTP 200).
     - Tạo snapshot revision và gọi `GET /api/v1/ai/story-brains/:storyBrainId/context-preview?chapterId=...` qua Node Gateway -> Backend suy luận chính xác `chapter_number` từ DB và AI Service trả về preview thành công (HTTP 200).
  7. **MongoDB Reachability**: Kết nối thành công tới MongoDB port 27017 từ pool backend.
- **Bằng chứng**:
  - `docs/development/P6.5-R5-FINAL-VERIFICATION-01/compose-live-smoke.txt`
  - `docs/development/P6.5-R5-FINAL-VERIFICATION-01/gateway-auth-smoke.txt`
