Policy and reproduced defect

An accepted AI revision and its outbox are immutable history. Cancellation never erases them. A skip/stop committed before an automatic canonical proposal acceptance or objective-completion transaction supersedes that attempt. No later automatic write may promote its pending proposals or overwrite skipped → completed. If an individual canon/progress transaction committed first, preserve it truthfully; cancellation is not a rollback of prior history. Multi-group canon acceptance consists of separate transactions: an earlier committed group remains, while cancellation fences every later group. Explicit authenticated author approval is an independent reconciliation decision and remains permitted; pending diagnostic extraction is not official canon.

`RED-pre-progress-skip/` is a genuine real-PG/Mongo/API reproduction before production repair. The worker paused after draft acceptance and human review but immediately before its old unconditional completed PATCH. Author skip succeeded, then release let that worker overwrite it as completed. Its expected-RED validation records the actual violation, not a mocked status. Existing pre-accept RED and all earlier evidence remain unchanged.

Implementation

`ai-service/infrastructure/controller_intent.py` loads the persisted generation key and validates its run/objective/epoch/pinned-plan/iteration/retry. It scopes novel/tenant and trusted request actor, checks current chapter and last generation, and verifies the exact immutable AI_DRAFT_ACCEPT revision/source_generation_id. It locks run → plan → objective before canon rows, matching the pre-accept lock order. The helper runs inside the same SQLAlchemy session/transaction as either proposal-group acceptance or objective completion. No provider or cross-service call is held inside these row locks. Author objective writes and run stop acquire the same corresponding rows, giving commit-order exclusion.

The authenticated AI router receives controller_intent {generation_id, revision_id}; actor comes from X-Actor-Id forwarded by the authenticated backend after ownership enforcement, never from client JSON and never by mutating shared repository state. Normal explicit author decisions omit controller_intent. In-memory/JSON controller writes fail closed because they cannot provide the durable PG boundary; ordinary author operations retain compatibility. No new schema migration was needed beyond existing AI 0013_objective_intent.

The backend supplies provenance to each automatic group acceptance and completed update. It handles OBJECTIVE_INTENT_SUPERSEDED/RUN_TERMINAL by returning durable current run state, without treating cancellation as a generation/provider failure. Recovery of an already accepted job now matches the entire current attempt key, including objective/epoch/plan/iteration/retry, rather than a run prefix alone. This prevents reuse of an older accepted attempt after ABA. A deliberately reactivated newer intent may legitimately generate a new candidate.
